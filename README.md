# ExoDRO

Trains an MLP by alternating with environments generated by the exogenous
generator and the SCM. The configuration below is the final setup after
hyperparameter search.

## Environment

Tested with: Python 3.11.9, PyTorch 2.4.1+cu121, pyro-ppl 1.9.1, NumPy 1.26.4.

`cloud_safe_tail.py` applies safe-tail handling for inputs outside the range
of the Pyro spline, so use this as the entry point.

## Required Inputs

Data and checkpoints are not included in this repository.
Point `EXO_INPUT_ROOT` to an existing experiment directory with the
following structure:

- `data/nominal/train.csv`
- `data/nominal/validation.csv`
- `data/ood_data/validation/`: 15 shared OOD validation environments
- `checkpoints/final_oodval/erm_seed{seed}_best.pt`: per-seed initial ERM
- `checkpoints/nominal_bound6/nominal_u{1,2,3,4}.pt`: bound-6 nominal generators

The same data and initial checkpoints must be used to compare against prior
experiments. The generator's bound is stored in the initial checkpoint being
loaded.

## Run Command

Run from the `Ours/` directory. The example below starts from the initial
ERM and nominal generator for seed 0. For other seeds, change `SEED` to 1–4.

```bash
export EXO_INPUT_ROOT=/path/to/Exo_DRO-data
SEED=0

CUDA_VISIBLE_DEVICES=0 python -u scripts/cloud_safe_tail.py \
  --train "$EXO_INPUT_ROOT/data/nominal/train.csv" \
  --validation-id "$EXO_INPUT_ROOT/data/nominal/validation.csv" \
  --validation-ood "$EXO_INPUT_ROOT/data/ood_data/validation" \
  --erm-checkpoint-dir "$EXO_INPUT_ROOT/checkpoints/final_oodval" \
  --generator-checkpoint-dir "$EXO_INPUT_ROOT/checkpoints/nominal_bound6" \
  --device cuda --sweep \
  --seed "$SEED" \
  --steps 16000 \
  --kl-budget 0.1 \
  --mlp-lr 0.003 \
  --generator-lr 0.001 \
  --dual-lr 0.01 \
  --inner-steps 10 \
  --selection-metric worst \
  --checkpoint-dir "checkpoints/ours_b6_kl0.1_seed${SEED}" \
  --log-dir "logs/ours_b6_kl0.1_seed${SEED}"
```

A per-run subdirectory is created under the checkpoint output path.
`last.pt` is the resumable state; `best.pt` is the state selected by
validation.

## Computation

### Model Structure and Parameter Count

| Component | Structure | Trainable Parameters |
|---|---|---|
| Predictor MLP (shared) | 4 → 64 → 64 → 1, ReLU | 4,545 |
| Exogenous generator (each of U1–U4) | N(0,1) base + 1D rational-quadratic spline (Pyro `Spline`, 8 bins, bound 6) | 23 per coordinate (width 8 + height 8 + derivative 7), **92** total |
| Constraint multipliers | 1 scalar per coordinate (dual ascent, not a trainable parameter) | — |

### Optimization Budget (final configuration, per seed)

| Item | Value |
|---|---|
| Outer steps | 16,000 (best checkpoint selected from 0–16,000) |
| Generator updates | 4 coordinates × K=10 = 40 per step → 640,000 total (Adam, lr 0.001) |
| MLP updates | 1 per step → 16,000 total (Adam, lr 0.003), 128 generated samples per update |
| KL estimation | 10,000 samples of the corresponding U from train, per generator update |
| Checkpoint evaluation | Every step: 15 OOD val environments (5,000 each) + ID val (2,000) |

### Runtime and Resources

| Item | Value |
|---|---|
| Hardware | AMD Ryzen Threadripper PRO 7995WX (96 cores / 192 threads), 251GB RAM. No GPU used |
| Software | Python 3.11.16, torch 2.4.1+cpu, numpy 1.26.4, pyro-ppl 1.9.1 |
| Execution | `--device cpu`, 1 CPU thread per run (`OMP_NUM_THREADS=1`), multiple runs concurrently |
| Time per step | ~0.14s standalone / 0.15–0.3s under concurrent runs |
| Final 5 seeds (16,000 steps) | 46–52 min per seed (8,000-step run: 25 min + continued training: 22–27 min; measured with 6–74 concurrent runs) |
| Memory per run | Up to ~0.3GB (RSS) |
| Full hyperparameter search | 104 runs, 48.4 core-hours total, 1h 49m wall-clock |

- Times are based on start/end timestamps in the per-run status file
  (includes program startup, data loading, and per-step evaluation).
- ERM checkpoint training and nominal generator pretraining (3,000 steps)
  time is not included.
- For reference: a GPU run (A5000, 2 per GPU) was reported at ~1.9s per step.

## Model Selection and Evaluation Rules

- Hyperparameters and the best checkpoint are selected by OOD validation
  worst MSE.
- The shared OOD validation environments are evaluated after each MLP
  update.
- The checkpoint with the lowest maximum MSE across environments is
  selected.
- OOD test is never used for hyperparameter or checkpoint selection.
- Final test evaluation is performed exactly once, using the selected best
  checkpoint.
